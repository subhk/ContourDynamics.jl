Tutorial: Quasi-Geostrophic Dynamics

This tutorial introduces the main quasi-geostrophic workflows in ContourDynamics.jl: single-layer QG, periodic domains with beta-plane staircases, and multi-layer QG.

Suggested reading order:

  1. start with the single-layer QG example
  2. then look at the periodic-domain example
  3. finally move to the multi-layer example

Each section uses the same overall workflow:

  • build contours
  • construct a Problem
  • evolve it in time
  • inspect diagnostics or geometry

Physical Background

Quasi-geostrophic (QG) dynamics describes rotating stratified flows at small Rossby number. Compared with 2D Euler, the main extra parameter is the Rossby deformation radius $L_d$, which sets the scale where rotation and stratification matter.

With the sign convention used by ContourDynamics.jl, the QG scalar kernel in the contour integral is:

\[G(r) = \frac{1}{2\pi} K_0\!\left(\frac{r}{L_d}\right)\]

Here $G$ is the scalar Green's function used by the contour integral, $r=|\mathbf{x}-\mathbf{x}'|$ is source-target distance, $L_d$ is the Rossby deformation radius (Ld), and $K_0$ is the modified Bessel function of the second kind, order zero. Two useful limits are:

  • For $r \ll L_d$: $K_0(r/L_d) \approx -\log(r/L_d)$, so the kernel behaves like Euler at small scales
  • For $r \gg L_d$: $K_0(r/L_d)$ decays exponentially, so interactions are screened at large scales

This means vortices smaller than $L_d$ behave like Euler vortices, while larger vortices are screened by rotation.

Single-Layer QG

julia> using ContourDynamics
julia> # QG vortex with deformation radius Ld = 2.0
       Ld = 2.02.0
julia> R, N, pv = 1.0, 32, 1.0(1.0, 32, 1.0)
julia> contour = circular_patch(R, N, pv)PVContour{Float64}: 32 nodes, Δq = 1.0, closed, centered at (-0.00, -0.00)
julia> prob = Problem(; contours=[contour], dt=0.05, kernel=:qg, Ld=Ld)Problem
├── ContourProblem{QGKernel, UnboundedDomain, Float64}
├── RK4Stepper{Float64}: dt = 0.05
└── surgery: δ=0.005, μ=0.02, Δ_max=0.2, every 5 steps
julia> println("Nodes: $(total_nodes(prob))")Nodes: 32
julia> println("Circulation: $(round(circulation(prob); digits=6))");Circulation: 3.121445
GPU Support

To run these QG workflows on GPU, add using CUDA and pass dev=GPU() when constructing the Problem.

Single-layer Euler, QG, and SQG (unbounded or periodic), beta-plane QG (periodic), and multi-layer QG all support device-resident velocity, RK4 timestepping, periodic wrapping, surgery, and diagnostics. Surgery on both unbounded and periodic domains runs entirely on the device; periodic reconnection uses minimum-image proximity and device-side cross-seam topology shifts.

At this stage, the only new ingredient compared with the Euler tutorial is the deformation radius Ld. Everything else about the high-level workflow is the same.

  • large Ld means weak screening, so QG looks close to Euler

Periodic Domains and Beta Staircases

For geophysical applications, doubly-periodic domains are essential. ContourDynamics.jl uses Ewald summation to handle the periodic Green's function efficiently.

Setting Up a Periodic Domain

julia> using ContourDynamics
julia> # A vortex patch in a periodic domain [-π, π) × [-π, π)
       R = 0.30.3
julia> contour = circular_patch(R, 24, 1.0)PVContour{Float64}: 24 nodes, Δq = 1.0, closed, centered at (-0.00, 0.00)
julia> L = Float64(pi)3.141592653589793
julia> prob = Problem(; contours=[contour], dt=0.05,
                      kernel=:qg, Ld=2.0, domain=:periodic, Lx=L, Ly=L)Problem
├── ContourProblem{QGKernel, PeriodicDomain, Float64}
├── RK4Stepper{Float64}: dt = 0.05
└── surgery: δ=0.005, μ=0.02, Δ_max=0.2, every 5 steps
julia> println("Domain half-widths: ($(L), $(L))")Domain half-widths: (3.141592653589793, 3.141592653589793)
julia> println("Nodes: $(total_nodes(prob))");Nodes: 24

The Ewald cache is built automatically on first use. For custom accuracy, pre-build with setup_ewald_cache!:

julia> # Higher accuracy: more Fourier modes and periodic images
       setup_ewald_cache!(domain(prob), kernel(prob); n_fourier=16, n_images=4)
julia> println("Ewald cache configured with n_fourier=16 and n_images=4");Ewald cache configured with n_fourier=16 and n_images=4

In most cases, setup_ewald_cache! does not need to be called explicitly. The default cache settings are adequate for typical problem sizes. Manual setup is primarily relevant when higher periodic-kernel accuracy is required.

Beta-Plane PV Staircases

The package includes a beta_staircase helper for constructing horizontal spanning contours in a periodic domain. With BetaPlaneQGKernel, these contours represent material regular-PV interfaces on a beta plane. The helper uses the Lam-Dritschel mid-step placement: n_beta contours at -Ly + (k - 1/2) * 2Ly / n_beta, each with jump beta * 2Ly / n_beta. The kernel keeps a reference copy of the initial straight staircase, subtracts that reference from the contour sum, then adds the analytic zonal correction for reference staircase - beta*y.

julia> using ContourDynamics
julia> T = Float64Float64
julia> L = 3.03.0
julia> domain = PeriodicDomain(T(L))PeriodicDomain{Float64}: x ∈ [-3.0, 3.0) × y ∈ [-3.0, 3.0)
julia> # Construct material full-PV jumps for beta-plane contour dynamics
       beta = T(1.0)1.0
julia> staircase = beta_staircase(beta, domain, 8; nodes_per_contour=16)8-element Vector{PVContour{Float64}}:
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
 PVContour{Float64}: 16 nodes, Δq = 0.75, spanning
julia> vortex = circular_patch(T(0.3), 32, T(2π))PVContour{Float64}: 32 nodes, Δq = 6.283185307179586, closed, centered at (-0.00, 0.00)
julia> prob = Problem(; contours=vcat(staircase, [vortex]),
                      dt=T(0.005),

julia> println("Number of spanning contours: $(length(staircase))")Number of spanning contours: 8
julia> println("PV jump per contour: $(staircase[1].pv)")PV jump per contour: 0.75
julia> println("Kernel: $(kernel(prob))");Kernel: BetaPlaneQGKernel{Float64}: beta = 1.0, Ld = 1.0, reference contours = 8

Each spanning contour has a wrap vector that connects the last node back to the first node shifted by one period. That is how the package represents contours that cross the periodic boundary.

That means the staircase contours are not ordinary closed loops sitting inside the box. They represent interfaces that continue across the periodic boundary.

The beta-plane setup combines three features:

  • a periodic Green's function through the Ewald machinery
  • active spanning-contour geometry for material beta contours
  • reference straight beta staircase subtraction in BetaPlaneQGKernel
  • analytic contour-only correction for the continuous beta*y term

The analytic correction is the finite-n_beta sawtooth residual from the discretized q_r - beta*y inversion. It keeps the implementation contour-based without replacing velocity evaluation by a grid solve.

Multi-Layer QG

For $N$-layer QG dynamics, the layers are coupled through interface deformation. The coupling is encoded in a coupling matrix that relates PV in each layer to the streamfunction.

Two-Layer Setup

julia> using ContourDynamics
julia> using LinearAlgebra
julia> using StaticArrays   # needed for SVector/SMatrix coupling matrix
julia> # Deformation radius of the baroclinic mode
       Ld = SVector(1.5)1-element StaticArraysCore.SVector{1, Float64} with indices SOneTo(1):
 1.5
julia> # Stretching operator with one barotropic mode (eigenvalue 0)
       # and one baroclinic mode
       F = 1.0 / (2 * Ld[1]^2)0.2222222222222222
julia> coupling = SMatrix{2,2}(-F, F, F, -F)2×2 StaticArraysCore.SMatrix{2, 2, Float64, 4} with indices SOneTo(2)×SOneTo(2):
 -0.222222   0.222222
  0.222222  -0.222222
julia> kernel = MultiLayerQGKernel(Ld, coupling)MultiLayerQGKernel{2, Float64}
├── Ld: [1.5]
├── layer thicknesses: [1.0, 1.0]
├── coupling: 2×2 SMatrix{Float64}
└── eigenvalues: [-0.4444444444444444, 0.0]
julia> println("Number of layers: $(nlayers(kernel))")Number of layers: 2
julia> println("Modal deformation radius: $(Ld[1])");Modal deformation radius: 1.5

The constructor automatically eigen-decomposes the coupling matrix. Each eigenmode is evolved independently using either the Euler kernel (barotropic mode) or a QG kernel with the appropriate modal deformation radius.

The package handles the eigen-decomposition and the projection back to physical layers internally.

For unequal depths, pass the raw physical coupling matrix together with the layer thicknesses. For example, $H=(1,3)$ and interface coefficients $F_1=0.6$, $F_2=0.2$ obey $H_1F_1=H_2F_2$:

julia> H_unequal = SVector(1.0, 3.0)2-element StaticArraysCore.SVector{2, Float64} with indices SOneTo(2):
 1.0
 3.0
julia> coupling_unequal = @SMatrix [-0.6 0.6; 0.2 -0.2]2×2 StaticArraysCore.SMatrix{2, 2, Float64, 4} with indices SOneTo(2)×SOneTo(2):
 -0.6   0.6
  0.2  -0.2
julia> Ld_unequal = SVector(1 / sqrt(0.6 + 0.2))1-element StaticArraysCore.SVector{1, Float64} with indices SOneTo(1):
 1.118033988749895
julia> unequal_kernel = MultiLayerQGKernel(Ld_unequal, coupling_unequal, H_unequal)MultiLayerQGKernel{2, Float64}
├── Ld: [1.118033988749895]
├── layer thicknesses: [1.0, 3.0]
├── coupling: 2×2 SMatrix{Float64}
└── eigenvalues: [-0.8, 0.0]
julia> unequal_kernel.symmetric_coupling2×2 StaticArraysCore.SMatrix{2, 2, Float64, 4} with indices SOneTo(2)×SOneTo(2):

The two-argument constructor can infer normalized thickness ratios from a connected nonsymmetric matrix, but supplying them explicitly preserves the physical Hamiltonian scale.

Creating a Multi-Layer Problem

julia> using ContourDynamics
julia> using StaticArrays
julia> R, N_nodes = 0.5, 32(0.5, 32)
julia> # Vortex in layer 1, no vortex in layer 2
       layer1_contours = [circular_patch(R, N_nodes, 2π)]1-element Vector{PVContour{Float64}}:
 PVContour{Float64}: 32 nodes, Δq = 6.283185307179586, closed, centered at (-0.00, -0.00)
julia> layer2_contours = PVContour{Float64}[]PVContour{Float64}[]
julia> prob = Problem(; layers=(layer1_contours, layer2_contours),
                      dt=0.01, kernel=:multilayer_qg,
                      Ld=Ld, coupling=coupling)Problem
├── MultiLayerContourProblem{2, UnboundedDomain, Float64}
├── RK4Stepper{Float64}: dt = 0.01
└── surgery: δ=0.005, μ=0.02, Δ_max=0.2, every 5 steps
julia> println("Total nodes: $(total_nodes(prob))")Total nodes: 32

This is the multi-layer analogue of the earlier single-layer Problem call: the only extra pieces are the layers tuple, Ld, and the coupling matrix. For unequal-depth input, add layer_thicknesses=H_unequal (and use its matching Ld_unequal and coupling_unequal).
